# Domain: ios-ci-stability

PurePace iOS 测试链路稳定性域：让 `bash scripts/test-ios.sh` 在**全新 macOS runner + 全新 iOS 18.6 模拟器**上可重复跑绿。当前契约已从「CI 内真实 `simctl location` 注入」切换为**UI 测试走 DEBUG + launch-arg 门控的确定性测试源**（`-uiTestLocation`），真实 CoreLocation 链路由 `scripts/verify-ios-sim-runtime.sh` 门独立覆盖；单测与 UI 测试拆成两次 `xcodebuild test`，单测结论先落盘不被 UI 失败吞掉，单次 attempt 静默等待 ≤600s，承载层重试仍最多 1 次。真实定位/距离计算、`RunLocationSource` 授权与采样契约、RunCore 与持久化/导出契约零改动，UI 断言一条不减。本机 `code_gates` 已收敛为 22 门：只留快而确定的腿，`test-ios` 本地门固定 `--unit-only`，模拟器重腿 `verify-ios-sim-runtime` / `verify-ios-ui-e2e` 不再本地阻断，全量单测 + UI 由 `.github/workflows/ios.yml` 的 `test` 步权威承载；同机多 worktree 的 iOS 门（`test-ios.sh` / `verify-ios-*.sh`）共用 `/tmp/purepace-ios-gate.lock` 串行化。预算口径已改为**按腿独立**：单测腿与 UI 腿各享一份 `IOS_XCODEBUILD_TIMEOUT`（默认 600s），UI 腿另有最小阈值（默认 300s），可用预算不足即显式打印一行并失败退出（不再被共享聚合算法饿死）；`ios.yml` 在 attempt2 之前先算 step 剩余预算，不足 900s 直接跳过重试并保留 attempt1 退出码；每次 attempt 输出经 `2>&1 | tee -a` 落盘、并以 `if: always()` 上传 3 天，SIGTERM 击杀也留 partial 日志。

## 范围

- `ios/PurePace/Location/RunTestLocationSource.swift`（新文件，整类型身处 `#if DEBUG ... #endif`）：实现既有 `RunLocationProviding`（`delegate` / `authorization` / `start()` / `stop()`），`start()` 后 ≤1s 产出首个 `RunSample`，之后约 1s 一个、纬度约 +0.000090°/s（≈10 m/s）推进，`horizontalAccuracy` 合法、授权等价 `authorizedWhenInUse`；不读写磁盘、不做播报。`ios/project.yml` 目录级 glob 自动纳入，需刷新时只 `xcodegen generate`。
- `ios/PurePace/ContentView.swift` 组合根（`@MainActor init()`）：`#if DEBUG` 分支内 `CommandLine.arguments.contains("-uiTestLocation")` → 注入测试源，否则保持 `RunLocationSource()`；生产路径不得引用测试源类型。
- `ios/PurePaceUITests/RunFlowUITests.swift`：`app.launchArguments += ["-uiTestLocation"]`；仍恰 2 个 `func test...`、≥68 处 `XCTAssert`；保留 ≤10s 首样本探针（`firstSampleProbeTimeout = 10`）、授权弹窗兜底与全部距离/暂停/恢复/结束/History/详情/导出/分享/播报持久化断言。
- `scripts/test-ios.sh`：`simctl bootstatus -b` → `simctl uninstall`（清容器与 TCC）→ `xcodebuild build` + `simctl install` → `simctl privacy grant location` → `simctl launch` + `terminate` 预热（`terminate` 后以 `xcrun simctl spawn "$sim_udid" launchctl list` 有界轮询 ≤10s 确认 `$bundle_id` 消失才返回；超界打印 `simulator-warmup` 阶段失败并 `exit` 非零）→ **两次** `xcodebuild test`（先 `-only-testing:PurePaceTests`，再 `-only-testing:PurePaceUITests` + `-skip-testing:PurePaceUITests/DeviceFlowUITests`；真机取证套件 `DeviceFlowUITests` 只由 `scripts/verify-ios-device-flow.sh` 分阶段驱动，不进默认 CI UI 腿），复用同一 `derivedDataPath`，日志分文件 `.build/logs/xcodebuild-unit.log` / `xcodebuild-ui.log`，单测 `Executed N tests` 摘要先 echo；脚本正文不含任何 `simctl location` 调用，改输出 `info: location-source=deterministic(-uiTestLocation)` 证据。新增 `--unit-only` 参数（只跑 `PurePaceTests`，`--help` 显式标注为本地门快腿）；`test_with_xcodebuild()` 前先取 `/tmp/purepace-ios-gate.lock`（`mkdir` 原子加锁、pid 文件、`PUREPACE_IOS_GATE_LOCK_HELD=1` 可重入、有界等待 1200s、无 pid 且 mtime >900s 视为陈旧锁删除、`trap` 释放），取锁后有界 600s 等 `xcodebuild|simctl` 归零再 `simctl shutdown all`。预算按腿独立：`unit_budget` / `ui_budget` 各取 `IOS_XCODEBUILD_TIMEOUT`（默认 600s），删除「UI 预算 = 600 − 单测已耗时」的共享聚合；UI 可用预算取 `min(ui_budget, step 剩余)`，低于 `PUREPACE_IOS_UI_MIN_BUDGET_SECONDS`（默认 300s）时打印 `test-ios: 承载层预算不足：UI 腿可用 … < 最小阈值 …` 一行并以非零（124）退出。
- `scripts/verify-ios-ui-e2e.sh`：UI 流不再依赖 `simctl location start`；默认证据根 `.build/verify-ios-ui-e2e/evidence`，仅显式 `--refresh-evidence` 才 copy 到 `docs/evidence/stage3-e2e/`；报告文案明确「UI/导出对齐由确定性测试源覆盖，真实 CoreLocation 由 verify-ios-sim-runtime 覆盖」；`--help` / 未知参数退出码契约不变；与 `test-ios.sh` 共用同一把 `/tmp/purepace-ios-gate.lock`（同语义可重入/陈旧清理/有界等待），重腿不再本地阻断、可手动串行执行。
- `scripts/verify-ios-sim-runtime.sh`：保持 1Hz 真实 `xcrun simctl location set` 注入；脚本仍在并共用同一把 iOS 门锁，但已不作为本地阻断门（见下条门禁拓扑）。
- `.munk/code-gates.json` 本地门禁拓扑（22 门）：只保留快而确定的 lint/build/test 腿，`test-ios` 门固定 `bash scripts/test-ios.sh --unit-only`；模拟器重腿 `verify-ios-sim-runtime` / `verify-ios-ui-e2e` 移出本地阻断（权威覆盖 = `.github/workflows/ios.yml` 的全量 `test-ios.sh`），既有其余门 id/command 语义不变。
- 结构门（只可加强）：`scripts/check-ios-scripts.sh` / `scripts/check-ios-shell.sh` 断言两次 `-only-testing` 调用与顺序、test-ios 无 `simctl location`、launch arg 存在、测试源 `#if DEBUG`、2 用例与 ≥68 断言、sim-runtime 真实注入仍在，每条新断言带负向自检；`check-ios-scripts.sh` 另断言 22 门拓扑、「重腿不得回到本地阻断门」「`test-ios` 门必须为 `--unit-only`」「workflow 不得出现 `--unit-only`（CI 必须跑全量 UI 腿）」，`check-ios-release.sh` / `check-android.sh` 的门数断言同步为 22。
- `.github/workflows/ios.yml`：`timeout-minutes: 45`、`infra_pattern`、`run_attempt 1/2` 均不变；`runner bootstrap 挂起` 字样继续由 `test-ios.sh` 输出以触发承载层重试。test 步骤开头 echo 一次 attempt 日志绝对路径（`${GITHUB_WORKSPACE:-$PWD}` 推导），导出 `PUREPACE_IOS_TEST_STEP_BUDGET_SECONDS`（默认 2700）与 `PUREPACE_IOS_STEP_STARTED_AT`（`date +%s`）；attempt 命令改 `bash scripts/test-ios.sh 2>&1 | tee -a <log>` 落 `.build/ci/test-ios-attempt{1,2}.log` 并以 `$?` 保留脚本退出码；attempt1 失败且命中承载层不稳定后先算 step 剩余，`< 900s` 则打印 `test-ios: 跳过重试，剩余 step 预算不足以跑完一轮` 并以 attempt1 退出码退出；新增 `test-logs` 步骤（`if: always()`、`actions/upload-artifact@v4`、`retention-days: 3`、`if-no-files-found: ignore`、只传两个 attempt 日志）。
- `AGENTS.md`：长期约定「CI UI 测试禁止依赖隐藏式 simulator 定位投递；UI 测试用 launch-arg 门控确定性测试源，真实 CoreLocation 覆盖放 `verify-ios-sim-runtime`（模拟器）/真机门」。
- 证据落点：`.munk/runs/<runId>/`（失败原始日志、`root-cause.md`、fix 说明、本机 clean run 日志、远端 run id 与 conclusion）；不写入仓库产品文件冒充证据。

## 验收

- ac-ui-tests-deterministic-source: `RunFlowUITests` 通过 `app.launchArguments` 传入 `-uiTestLocation` 启动 App；在没有任何 `simctl location` 投递的 hosted runner 上，开跑后 10s 内距离从 `0.00 km` 发生变化。
- ac-ui-assertions-intact: `RunFlowUITests` 仍恰有 2 个 `func test...`，`XCTAssert*` 出现次数不低于 68；距离增长、暂停/继续、结束保存、History 出现 1 条、详情/导出/分享、播报开关跨重启持久化等断言全部保留。
- ac-test-source-debug-and-arg-gated: 确定性测试源整体位于 `#if DEBUG`；仅当启动参数 `-uiTestLocation` 存在时由 `ContentView` 组合根注入；参数缺失或 Release 构建时仍使用 `RunLocationSource`；测试源只实现既有 `RunLocationProviding` / delegate 契约，首个样本 ≤1s、之后约 1s 一个、约 10 m/s 推进，授权等价 `authorizedWhenInUse`。
- ac-production-location-unchanged: `RunLocationSource` 仍用 `CLLocationManager`、`requestWhenInUseAuthorization`、`activityType = .fitness`、`distanceFilter = kCLDistanceFilterNone`、`pausesLocationUpdatesAutomatically = false`；RunCore 距离/配速/分段、播报、持久化、GPX 导出契约零改动。
- ac-test-ios-two-invocations: `scripts/test-ios.sh` 在 bootstatus 之后先跑 `-only-testing:PurePaceTests` 再跑 `-only-testing:PurePaceUITests`（UI 腿同时带 `-skip-testing:PurePaceUITests/DeviceFlowUITests`）；两次调用日志/结果分文件，单测摘要先于 UI 输出；任一失败脚本非零退出，单测通过结论不被 UI 失败覆盖；脚本正文不再出现任何 `simctl location` 调用。
- ac-ui-leg-skips-device-flow: UI 腿选择器在**同一份源码的三处**必须一致——`usage()` 帮助文本（`-only-testing:PurePaceUITests` 行或其紧邻续行）、`echo "info: xcodebuild ..."` 行（与 `-only-testing:PurePaceUITests` 同行）、实际 `xcodebuild test-without-building` 参数块（`-only-testing:PurePaceUITests \` 独占一行后紧跟 `-skip-testing:PurePaceUITests/DeviceFlowUITests \`）——均含 `-skip-testing:PurePaceUITests/DeviceFlowUITests`；重试路径复用同一函数，故两次 attempt 选择器天然一致。
- ac-unit-leg-no-skip: 单测腿仍为 `-only-testing:PurePaceTests`，其参数块内**不含**任何 `-skip-testing:`。
- ac-single-file-diff: 本项改动面只有 `scripts/test-ios.sh`（`git diff --name-only origin/main...HEAD` 仅此一路径）。
- ac-no-ci-weakening-and-suite-intact: 未引入 `continue-on-error` / allowed-failure、未删腿、未抬高 600s 预算或任何超时字面量、未弱化断言；`ios/PurePaceUITests/DeviceFlowUITests.swift` 保持 4 条用例原样并继续由 `scripts/verify-ios-device-flow.sh` 分阶段驱动；`bash scripts/check-ios-scripts.sh` 全绿（其顺序锚点要求 `-only-testing:PurePaceTests` 行先于 `-only-testing:PurePaceUITests` 行，skip 行不得与 `-only-testing:PurePaceUITests` 合并成一行或调换顺序）。
- ac-watchdog-and-retry-preserved: `IOS_XCODEBUILD_TIMEOUT` 默认值仍 ≤600s（单测腿 / UI 腿**各一份独立预算**，不再聚合扣减），两个 `xcodebuild test` 调用仍带 `-test-timeouts-enabled YES` / `-default-test-execution-time-allowance 300` / `-maximum-test-execution-time-allowance 540`；`.github/workflows/ios.yml` 的 `timeout-minutes` 不放大，承载层重试仍为 1 次。
- ac-budget-per-leg-independent: 单测腿与 UI 腿各自获得独立上限（`IOS_XCODEBUILD_TIMEOUT` 默认 600s 各一份）；源码中不再出现把 `xcodebuild_timeout - (SECONDS - started_at)` 作为 UI 预算的表达式。
- ac-ui-min-budget-threshold: `PUREPACE_IOS_UI_MIN_BUDGET_SECONDS` 未设置时最小阈值为 300s；显式设为 N 时以 N 为准。
- ac-ui-budget-below-min-fails: UI 腿可用预算 < 最小阈值时，脚本恰好输出一行前缀逐字为 `test-ios: 承载层预算不足：UI 腿可用 ` 的提示（形如 `test-ios: 承载层预算不足：UI 腿可用 120s < 最小阈值 300s`）并以非零退出；不得改写为通过、不得使用 `continue-on-error`。
- ac-retry-skip-low-step-budget: `PUREPACE_IOS_TEST_STEP_BUDGET_SECONDS` 与 `PUREPACE_IOS_STEP_STARTED_AT` 均存在且 attempt1 失败后剩余 step 预算 < 900s 时，不启动 attempt2，输出一行 `test-ios: 跳过重试，剩余 step 预算不足以跑完一轮`，最终退出码等于 attempt1 的退出码。
- ac-retry-default-unchanged: 未设置上述 step 预算 env（本地/旧调用）时，重试判定与现状一致：命中承载层特征仍重试 1 次，attempt1/attempt2 日志仍分文件。
- ac-step-budget-env-wired: `ios.yml` 的 test 步骤向 `scripts/test-ios.sh` 传递 `PUREPACE_IOS_TEST_STEP_BUDGET_SECONDS`（默认 2700）与 `PUREPACE_IOS_STEP_STARTED_AT`（step 起始 epoch 秒）；step 超时仍为 45 分钟。
- ac-attempt-log-durable: 每次 attempt 输出经 `2>&1 | tee -a <attempt log>`（或等价非 SIGPIPE 写法）落盘；进程被 SIGTERM/超时击杀后日志文件仍保留击杀前已产生的行；attempt 退出码仍取 `scripts/test-ios.sh` 的退出码，不被 tee 覆盖。
- ac-upload-artifact-always: `ios.yml` 含 `actions/upload-artifact` 步骤，配置 `if: always()`、`retention-days: 3`、只上传 attempt 日志文件（不上传整个目录），文件缺失时不额外判红（`if-no-files-found: ignore`）。
- ac-log-abs-path-echoed: test step 开头 echo 一次 attempt 日志绝对路径（可用 `$GITHUB_WORKSPACE` 或 `$PWD` 推导），不重复刷屏。
- ac-pass-fail-lines-unchanged: 同一输入下，改造前后 `scripts/test-ios.sh` 的 PASS/FAIL 行集合完全一致，仅允许多出 `test-ios: 承载层预算不足：…` 与 `test-ios: 跳过重试，剩余 step 预算不足以跑完一轮` 两条显式提示行。
- ac-no-sigpipe-and-syntax: 新增/改动的判定不得引入 `cmd | grep -q` 等在 `set -euo pipefail` 下可能触发 SIGPIPE(141) 的写法（用 here-string）；`bash -n scripts/test-ios.sh` 为 0。
- ac-determinism-and-evidence: 用 env 注入假时长演示三处行为并留 dry-run 输出；关键判定逻辑连跑 20 次结果恒同并留证；本地 `code_gates` 的 unit + build + lint 腿绿；UI E2E 权威结论只认 `ios.yml`，不得以本地绿替代。
- ac-real-corelocation-gate-kept: `scripts/verify-ios-sim-runtime.sh` 仍以 1Hz `xcrun simctl location set` 真实驱动 corelocation 链路并由 `check-ios-scripts.sh` 的 `ac-real-corelocation-gate-kept` 断言守住；该重腿已移出本地阻断门（`code-gates.json` 不再含 `verify-ios-sim-runtime`），权威落点为 `.github/workflows/ios.yml` 全量 `bash scripts/test-ios.sh`（workflow 出现 `--unit-only` 即判失败）。
- ac-structure-gates-strengthened: `check-ios-scripts.sh` / `check-ios-shell.sh` 新增断言覆盖上述契约（UI 路径无 `simctl location`、存在 `-uiTestLocation`、测试源 `#if DEBUG`、2 个用例与 ≥68 断言、sim-runtime 真实注入仍在），每条断言都有会失败的负向自检样本；`.munk/code-gates.json` 现为 22 门（快腿拓扑）且全绿。
- ac-warmup-no-terminate-race: `scripts/test-ios.sh` 在 `simctl terminate "$bundle_id"` 之后、`xcodebuild test` 之前轮询 `xcrun simctl spawn "$sim_udid" launchctl list` 直到 `$bundle_id` 消失才返回；源码中不存在「`terminate` 后直线进入 `xcodebuild`」路径。
- ac-warmup-bounded: warmup 轮询有明确上界（≤10s、有限迭代），超界打印 `simulator-warmup` 阶段失败并 `exit` 非零；不依赖裸 `sleep` 定时器、不无限重试；`test-ios.sh` 仍含 `simctl launch` 与 `simctl terminate` 字样（`check-ios-scripts.sh` 门禁字面量不被削弱）。
- ac-ios-gate-lock-serialized: `scripts/test-ios.sh` / `scripts/verify-ios-sim-runtime.sh` / `scripts/verify-ios-ui-e2e.sh` 内建同一把 `/tmp/purepace-ios-gate.lock`：`mkdir` 原子取锁 + pid 文件、`PUREPACE_IOS_GATE_LOCK_HELD=1` 可重入、有界等待（1200s）后非零退出、无 pid 且 mtime >900s 视为陈旧锁删除、`trap` 释放；取锁后先有界等 `xcodebuild|simctl` 归零再 `simctl shutdown all`，有并发时不执行 shutdown/erase。
- ac-local-gates-fast-only: 本机 `code_gates` 拓扑为 22 门且只含快而确定腿；`test-ios` 门 `command` 恰为 `bash scripts/test-ios.sh --unit-only`，`verify-ios-sim-runtime` / `verify-ios-ui-e2e` 不在本地门集合中；`.github/workflows/ios.yml` 仍执行全量 `bash scripts/test-ios.sh` 且不含 `--unit-only`；`check-ios-release.sh` / `check-android.sh` 的 22 门断言与之一致。
- ac-evidence-no-churn: 直接运行 `scripts/verify-ios-ui-e2e.sh` 只更新 `.build/` 产物，`docs/evidence/stage3-e2e/` 保持 git 干净；带 `--refresh-evidence` 时才覆盖仓库证据目录，且 `--help` / 未知参数退出码契约不变。
- ac-agens-ci-rule: 仓库 `AGENTS.md` 含长期约定：CI 的 UI 测试禁止依赖隐藏式 simulator 定位投递，UI 测试用确定性测试源，真实定位覆盖放 e2e（模拟器）/真机门。
- ac-boot-warmup: 脚本在 `simctl bootstatus <udid> -b` 通过后才继续；随后完成一次安装/启动预热（`simctl launch` + `terminate` + 有界 `launchctl list` 轮询确认进程消失），boot 或预热失败即非零退出并打印设备 udid 与阶段，不静默跳过、不降级为通过。
- ac-sim-privacy-granted: 顺序铁律「`simctl uninstall` 清容器 → 构建安装 → `simctl privacy grant location` → `xcodebuild test`」，授权命令在安装之后、测试之前且可被脚本源码断言。
- ac-location-callback-diagnostics: 模拟器下仍记录 CoreLocation 授权状态与样本/过滤计数到 App 沙盒 `Documents/location-diagnostics.log`，仅 `#if targetEnvironment(simulator)` 路径，不改变真机行为与业务契约。
- ac-e2e-no-hidden-injection: `scripts/verify-ios-ui-e2e.sh` 与 `scripts/test-ios.sh` 均不再调用 `simctl location set/start` 驱动 UI 断言；真实注入只允许出现在 `verify-ios-sim-runtime.sh`。
- ac-local-two-green: 本机干净模拟器（先 `simctl shutdown all` + `simctl erase <udid>`）连续 2 次 `bash scripts/test-ios.sh` 全绿，日志含确定性测试源证据与 `** TEST SUCCEEDED **`。
