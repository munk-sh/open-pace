# 距离恒 0 根因结论 + 三态读数协议 + W1 新断言变异红证

## 范围

- 基于已合入 main 的 W1 代码（`c381352`：`ios/PurePace/Location/RunLocationSource.swift`、`Run/RunLocationReadiness.swift`、`Run/RunLocationSearchState.swift`、`Run/RunDiagnostics.swift`）给出「WiFi 有网 / WiFi 关+蜂窝 / 飞行模式」三态下距离恒 0 的根因结论：分清是系统不回调、回调被精度过滤丢弃、还是被降级窗口吞掉，引用真实文件与符号名，不臆造。
- 产出：仓内 `docs/` 下一份结论文档（≤1 个新文件）+ `docs/evidence/<本项 workItemId>/` 下的复现日志与变异日志。
- 对 W1 本轮新增断言做变异红证：在 `/tmp` 副本上逐组构造错误输入，实际执行并记录「测得红」的日志；禁止改仓内生产代码。
- 写一份「真机三态读数自采集」读屏协议：只写点哪里、看诊断区哪几行、什么算异常，不含任何命令行。

## 验收

- ac-rootcause: 结论文档给出根因链条（代码路径 + 触发条件 + 与三态网络形态的对应关系），每条能对上仓内真实文件与符号名。
- ac-repro: 证据目录含实际执行产生的复现日志（时间 / 输入 / 读数），并逐项标「机器侧可复现」或 `pending: 待人现场`。
- ac-mutation: W1 新增断言各有一条「构造错误输入 → 实际测得红」的日志并写进文档路径索引；日志来自真实执行，不得改仓内生产代码。
- ac-protocol: 读屏协议覆盖三态 × ≥30s 的 raw 回调数 / 精度丢弃数 / 授权状态 / 精度授权 / 后台标志，人可按步执行且不含命令。
- ac-scope: 本项只新增 docs/ 与 docs/evidence/ 内容，diff 不含生产代码、不含新测试与脚本改动。

## 非目标

- 不改生产代码、不修根因、不调阈值、不新增或删除断言。
- 不跑真机、不代填三态真机读数（一律记 `pending: 待人现场`）。
- 不碰 W2 / W3 的文件（`SettingsView` / `HistoryView` / `RunDetailView` / `RunInteractionPlan` / `DesignTokens`）。
- 不新建第二套文档体系、不改 verification-matrix 的全局行数。

## 实现约束

- 文档沿用仓内既有 `docs/` 与 `docs/evidence/` 结构，结论文档 ≤1 个新文件。
- 变异红证只在 `/tmp` 副本上做，日志必须来自实际执行；每个数字标口径（测试类 / 用例 / 注入输入）。
- 反馈环优先：需要跑测试时只跑单个测试类（≤60 秒），禁跑全量门、禁反复重读同一文件（同一文件重读 >1 次即停）。
- 整文件写入，禁逐点微编辑。

## 本单执行约束（不 fold）

- 预算 ≤2M token / ≤60 分钟墙钟；到 1M 或 30 分钟先 WIP commit + 一条进度回执（已做 / 未做 / 红在哪），再决定继续或交棒。
- commit 按面拆分：文档与证据一律 fold 面，禁止与 code 面混提；本项预期只有 fold 面。
- 发现要改生产代码才能证明的结论，写进「未闭合点」交回执，不自行扩范围。
