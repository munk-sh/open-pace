# 保存后可立刻再跑：结束页主操作 + 任一入口回起跑

## 范围

- 保存成功页（结束态保存后）主操作改为「再跑一次」：点击回到 ready 并可直接开始新一次记录；「查看历史」降为次操作（文字按钮或无填充次要样式）。一屏只有一个主操作，禁两枚等权描边按钮并排。
- 任一入口一键回起跑：Tab 栏存在时点「跑步」tab 从历史列表 / 历史详情 / 设置回到 ready 起跑入口；历史列表与历史详情页内各提供一个回到起跑入口的动作（复用同一条路由，不新建第二套导航）。
- 状态机收口：保存后再跑、丢弃、新跑都必须收敛回 ready，不残留 finished / saving 状态、不残留旧会话计时或采样点；断言覆盖「保存后再跑状态为 ready」「丢弃后状态为 ready」「新跑不继承上一次数据」。
- 断言：①保存成功页存在起跑动作（用 identifier / 层级断言，不只靠文案）②点按后进入 ready 且可立即开始 ③历史列表、历史详情、设置三处均能回起跑 ④状态回 ready 且数据清零。

## 验收

- ac-rerun-primary：保存成功页存在「再跑一次」主操作，且「查看历史」为次操作（可断言的层级 / 样式差异，非仅文案比对）。
- ac-rerun-ready：点「再跑一次」后进入 ready，能立即开始记录（模拟器 UI 断言）。
- ac-rerun-tabs：历史列表、历史详情、设置三处各存在回起跑入口，点按后到达 ready（三个用例各一条）。
- ac-rerun-state：保存后再跑、丢弃后都收敛回 ready，计时 / 距离 / 采样点全部清零；断言附造错必红反例。
- ac-rerun-nostale：上一次会话残留数据不会带进新跑（构造断言 + 反例）。
- ac-rerun-redcounter：每条新断言同 commit 附造错必红证据，反例原文贴回执。

## 非目标

- 不改记录中 / 暂停中的界面结构与既有主操作语义。
- 不做设置 / 历史列表 / 历史详情三屏视觉改造（W3 负责）。
- 不做自动开跑、不加社交 / 分享 / 账号功能、不改 GPX 与存档格式、不动 Android 侧。

## 实现约束

- 复用既有路由与状态机，不新建第二套导航栈；identifier 只增不改，a11y label 用中文且语义一致。
- 文案走 String Catalog（zh-Hans 单语）；`DesignTokens.swift` 唯一令牌来源，视图层零字面色值、零裸 magic number。
- 底栏在记录态 / 结束待保存态仍收起，回到 ready 才恢复；「任一入口回起跑」不得破坏该约定。
- 同一 commit 的 `ios.yml` 全绿；如改受管视图或 identifier，显式跑 `scripts/check-ios-shell.sh --self-test` 全绿；测试文件 ≤400 行、Swift 源 ≤500 行。

- 不自建 / 删除远端仓库、不改 remote、本项不 push / merge / PR。
