# PurePace 真机手测手册

真机不做 agent 验收：agent 与 CI 只跑模拟器，本手册供交付后由人手在真机上执行。
按本页顺序执行，全程 ≤5 分钟；失败时只记录现场现象与包/commit 身份，不改代码、不做现场调试。

**使用前提（三条，做完再开跑）**

- 干净安装：先删掉机上的 PurePace，再安装候选包；不在旧版本上覆盖升级。
- 版本号：以根 `VERSION` 为单一真源，当前 `0.1.0`；机上显示的版本必须是它。
- 构建身份：记下候选 zip 的 `sha256` 与构建来源 commit 全 sha（写法见第 3 节）。

## 1. 核心闭环（四个检查点，按顺序做完即通过）

1. **真机开跑**：用候选包在真机点「开始跑步」，走到室外等定位；记录中按一次暂停、几秒后继续。
   通过判据：界面进入记录态，距离与用时都在走；暂停时两者停住，继续后恢复增长。
2. **开跑后按电源键锁屏并保持 ≥1 分钟**：在记录态按电源键锁屏，保持 ≥60 秒。
   通过判据：屏幕熄灭，无崩溃弹窗；记录态与计时是否保住由检查点 3 一次判完。
3. **解锁回前台看距离曲线与计时**：点亮并解锁，回到 PurePace 前台。
   通过判据：仍处记录态、计时继续走、App 未崩溃；距离变化只作观察项（见第 2 节）。
4. **结束保存 → 历史选中本次 → 导出 GPX**：点结束并保存；进历史选本次记录看到详情；点导出 GPX。
   通过判据：本次记录出现在历史列表且详情与本次一致，GPX 导出成功并能在「文件」App 看到该文件。

四个检查点都顺即为闭环通过；任一步失败即记为该次手测失败，并记录包身份与现场现象。

## 2. 锁屏与解锁（≥1 分钟）

1. 在记录态记下锁屏前的距离与用时（只记两个数字，不采集波形、不比对数表）。
2. 按电源键锁屏，保持 ≥60 秒。
3. 点亮并解锁，回到 PurePace 前台，记下解锁后的距离与用时。

通过判据只看三条：

- 仍处记录态：回到前台仍是同一条记录的计时界面，未退出、未退回首页；
- 计时继续走：解锁后的用时大于锁屏前用时，秒数仍在增长；
- App 未崩溃：解锁后界面正常可操作，无闪退。

距离增长只作观察项：**静止段不要求距离增长**，锁屏前后的距离变化以 GPS 漂移为上限，不得把「距离必须增长」当作通过条件。

## 3. 构建身份标注

手测前先写清「用哪个包 / 哪个 commit 测」，两者都要落到记录里：

- 包：候选 zip 与其 `sha256`；
- commit：构建来源 commit 全 sha（可加短 sha 便于对照）。

双 sha（候选 zip 的 `sha256` + commit）只作记录，不构成脚本校验流程，也不要求任何人重算比对。
历史候选仅作示例：`sha256 7258d2e3…b9d8f` / commit `8db1a167`。

## 4. 人耳判定（≤2 条）

1. 每公里播报是否听清（距离、配速、用时能否听清并听懂）。
2. 播其他音乐时音乐是否被打断、播完是否恢复。

两条只凭耳朵判定，不采集波形、不比对数表；听不清或音乐没恢复就写「未通过」，不写「大概可以」。

## 5. 系统定位权限（三步）

设置 → 隐私与安全 → 定位服务 → 找到 PurePace → 选「始终允许」。
换机或重装后必做一次；未授权时后台记录会中断，先做这步再开跑。

## 6. 状态语义（pending: 待人现场）

- 未在真机上按本手册做过，一律写 `pending: 待人现场`；
- 只有人手实测完成并给出结论，才能把该项改成通过/未通过；
- 禁写「真机已验证」：没有现场记录就没有真机结论，模拟器通过不等于真机通过。

本手册不含自动化驱动步骤（XCUITest / simctl / 脚本）：真机项只由人手执行，脚本与 CI 不代跑。
